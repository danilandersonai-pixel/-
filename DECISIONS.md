- **29.09.2026** — В `consents` добавлен `revokedAt` — отзыв согласия. Без действующего согласия закрыты здоровье, замеры и прогресс.
- **29.09.2026** — `health` — одна запись на подопечного (уникальный индекс). `nutrition_plans` — история: текущий план — последний по дате начала.
- **29.09.2026** — Тренировка сохраняется так: упражнения и подходы записываются по одному, убранные удаляются в конце. Вариант «удалить всё и записать заново» отклонён: сбой посередине стёр бы тренировку.
- **29.09.2026** — Резервная копия — JSON со всеми таблицами, без фото (фото — файлы на телефоне). Восстановление из копии пока не сделано.
- **29.09.2026** — Копия теперь ZIP: `backup.json` + папка `photos` (версия формата 2). Старые JSON-копии (версия 1) тоже восстанавливаются. ZIP выбран, чтобы копию можно было открыть на компьютере (варианты: фото base64 внутри JSON — файл на треть больше и целиком в памяти).
- **29.09.2026** — ZIP пишу и читаю своим модулем `src/lib/zip.ts` без сжатия (JPEG почти не сжимается), без библиотеки. Формат простой, запись и чтение идут по одному фото, без загрузки всей копии в память. Проверено программой `unzip`. Вариант fflate отклонён: лишняя зависимость ради того же.
- **29.09.2026** — Восстановление — слияние, а не замена: ничего не удаляется, новая запись добавляется, из двух версий одной записи остаётся более новая (`updatedAt`). Тренировка из копии приходит вместе со своими упражнениями и подходами. Перед записью — экран «Что изменится». Вариант «стереть всё и загрузить копию» отклонён: старая копия затёрла бы свежие данные.
- **29.09.2026** — Фото теперь хранятся в базе относительным путём `photos/<id>.jpg`. На iPhone полный путь к папке приложения меняется после обновления, и старые пути ломаются. Старые записи с полным путём понимаются по имени файла.
- **29.09.2026** — В превью все модули работают с одной таблицей localStorage на имя (`browserTable`), иначе восстановление в одном модуле не видели бы другие.

## Калькулятор

- **29.09.2026** — Возраст для формул — на дату замера, а не на сегодня. Иначе старые замеры «пересчитываются», когда клиент стареет.
- **29.09.2026** — Если складки начаты, но не все, а обхваты есть — основной % жира по обхватам и подсказка, каких складок не хватает.
- **29.09.2026** — Изменения к прошлому замеру и графики % жира (и масс от него) — только одним методом. Складки и обхваты расходятся на несколько процентов, сравнение разных методов нечестно.
- **29.09.2026** — Погрешности: ВМС ±4 % (верхняя граница из «±3–4 %»), JP3 ±3,5 %, Lee ±2,2 кг, Boer — не оцениваем. % жира вне 2–70 % считаем ошибкой замера.
- **29.09.2026** — Поправка на расу в формуле Lee = 0 (европеоидная), отдельного поля нет.
- **29.09.2026** — В питании добавлен базовый обмен по Миффлину — Сан Жеору как справка с кнопкой «?». В CLAUDE.md его нет, но тренеру полезен ориентир.

- **29.09.2026** — Цвета графиков и КБЖУ проверены валидатором на контраст и различимость при нарушениях цветовосприятия, для каждой темы свои оттенки.

- **29.09.2026** — Блок «Сегодня» — карточка вверху экрана «Подопечные», а не отдельная вкладка: CLAUDE.md задаёт три вкладки. При поиске блок прячется, пустой не показывается.

Рекорд — вырос лучший вес или 1ПМ (без веса — повторы); первая тренировка рекордом не считается. Упражнения объединяются по названию без учёта регистра, пробелов и «ё».

## Связь и выгрузка

- **29.09.2026** — Кнопки связи — только ссылки для системных приложений (`tel:`, `wa.me`, `t.me`); приложение само ничего не отправляет. Российские номера с 8 и без кода страны приводятся к +7. Telegram — только если в поле «Мессенджер» ник или ссылка t.me. В демо-данных мессенджеров нет: вымышленный ник мог бы оказаться чьим-то настоящим.
- **29.09.2026** — CSV: разделитель «;», дробная запятая, UTF-8 с BOM, строки через CRLF — так русский Excel открывает файл сразу. В таблицу попадают и измеренные значения, и расчёты (с методом % жира).

## Замеры и цели

- **29.09.2026** — Цель — отдельная таблица `goals` (миграция 0006): показатель, значение, срок (необязателен), дата старта. Действующая — последняя неудалённая, удаление — пометкой. Прогресс и прогноз не храним: считаются из замеров.
- **29.09.2026** — Прогноз цели — прямая по методу наименьших квадратов по замерам за последние 90 дней (минимум две точки на расстоянии от недели). Дальше трёх лет — «темп не ведёт к цели»: такой прогноз бессмыслен.
- **29.09.2026** — Сравнение двух замеров: % жира и массы от него в обоих — методом более нового замера, как на графиках.
- **29.09.2026** — «Шторка» для фото — на встроенной системе касаний React Native (прозрачный слой ловит палец), без библиотек жестов. Для экранного диктора — «настраиваемый» элемент с шагом 10 %.
- **29.09.2026** — Второстепенные действия вкладки «Замеры» собраны в сетку 2×2 из плиток, чтобы не было столбика из пяти кнопок.

## Тренировки и абонементы

- **29.09.2026** — Абонемент — отдельная таблица `memberships` (миграция 0007): сколько тренировок куплено, дата начала, срок (необязателен), заметка. Действующий — с самой поздней датой начала; старые остаются в истории. Остаток не храним: считаем по проведённым тренировкам в сроке абонемента, поэтому отметка «Проведена» сразу уменьшает остаток. Оплаты не принимаем — это только счётчик.
- **29.09.2026** — «Заканчивается» — когда осталось 2 тренировки или меньше: время предложить продление до последнего занятия.
- **29.09.2026** — Серия тренировок создаётся сразу отдельными запланированными тренировками, а не «правилом повтора»: каждую можно перенести или удалить по одной, календарь и счётчики работают без изменений. Дни, где у подопечного уже есть тренировка, пропускаются. Упражнения в серию не копируются — для этого есть «Повторить прошлую».
- **29.09.2026** — Таймер отдыха — на обычном `setInterval` и времени окончания (а не счётчике секунд), поэтому не сбивается, если приложение свернули. Сигнал — встроенная `Vibration` React Native, без новых библиотек. Первым предлагается отдых из последнего заполненного подхода.
