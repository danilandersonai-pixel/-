## Данные

- **29.09.2026** — Время хранится числом миллисекунд, даты — строкой `ГГГГ-ММ-ДД`. Почему: не зависит от часового пояса, удобно сортировать.
- **29.09.2026** — В `workouts` добавлен `status` (`planned` / `done`): без него нельзя показать «следующую тренировку».
- **29.09.2026** — Замеры, фото и тренировки удаляются пометкой `deletedAt`, строка остаётся. Почему: CLAUDE.md запрещает удалять насовсем, пометки пригодятся для синхронизации с облаком.
- **29.09.2026** — В `consents` добавлен `revokedAt` — отзыв согласия. Без действующего согласия закрыты здоровье, замеры и прогресс.
- **29.09.2026** — `health` — одна запись на подопечного (уникальный индекс). `nutrition_plans` — история: текущий план — последний по дате начала.
- **29.09.2026** — Тренировка сохраняется так: упражнения и подходы записываются по одному, убранные удаляются в конце. Вариант «удалить всё и записать заново» отклонён: сбой посередине стёр бы тренировку.
- **29.09.2026** — Резервная копия — JSON со всеми таблицами, без фото (фото — файлы на телефоне). Восстановление из копии пока не сделано.
- **29.09.2026** — Копия теперь ZIP: `backup.json` + папка `photos` (версия формата 2). Старые JSON-копии (версия 1) тоже восстанавливаются. ZIP выбран, чтобы копию можно было открыть на компьютере (варианты: фото base64 внутри JSON — файл на треть больше и целиком в памяти).
- **29.09.2026** — ZIP пишу и читаю своим модулем `src/lib/zip.ts` без сжатия (JPEG почти не сжимается), без библиотеки. Формат простой, запись и чтение идут по одному фото, без загрузки всей копии в память. Проверено программой `unzip`. Вариант fflate отклонён: лишняя зависимость ради того же.
- **29.09.2026** — Восстановление — слияние, а не замена: ничего не удаляется, новая запись добавляется, из двух версий одной записи остаётся более новая (`updatedAt`). Тренировка из копии приходит вместе со своими упражнениями и подходами. Перед записью — экран «Что изменится». Вариант «стереть всё и загрузить копию» отклонён: старая копия затёрла бы свежие данные.
- **29.09.2026** — Фото теперь хранятся в базе относительным путём `photos/<id>.jpg`. На iPhone полный путь к папке приложения меняется после обновления, и старые пути ломаются. Старые записи с полным путём понимаются по имени файла.
- **29.09.2026** — В превью все модули работают с одной таблицей localStorage на имя (`browserTable`), иначе восстановление в одном модуле не видели бы другие.

## Калькулятор

- **29.09.2026** — Возраст для формул — на дату замера, а не на сегодня. Иначе старые замеры «пересчитываются», когда клиент стареет.
- **29.09.2026** — Если складки начаты, но не все, а обхваты есть — основной % жира по обхватам и подсказка, каких складок не хватает.
- **29.09.2026** — Изменения к прошлому замеру и графики % жира (и масс от него) — только одним методом. Складки и обхваты расходятся на несколько процентов, сравнение разных методов нечестно.

- **29.09.2026** — Поправка на расу в формуле Lee = 0 (европеоидная), отдельного поля нет.
- **29.09.2026** — В питании добавлен базовый обмен по Миффлину — Сан Жеору как справка с кнопкой «?». В CLAUDE.md его нет, но тренеру полезен ориентир.
