# CLAUDE.md — «Спортивный Треккер» (приложение тренера)

## О проекте

Мобильное приложение для персонального тренера в тренажёрном зале: «спортивная тетрадь», где собрано всё
о каждом подопечном. Это профиль и контакты, здоровье, замеры тела, тренировки, питание и прогресс.

Главная фишка: **встроенный калькулятор состава тела**. Тренер вводит замеры, приложение само считает
% жира, жировую, безжировую и мышечную массу и показывает, по какой формуле и с какой погрешностью.

Этапы:
1. **Сейчас:** приложение для тренера (MVP), данные хранятся только на телефоне.
2. **Потом:** облако и отдельное приложение для подопечных. Пока их не делаем, но архитектуру
   закладываем так, чтобы потом их можно было добавить без переписывания.

## Экраны MVP

1. **Список подопечных** — фото, имя, цель, следующая тренировка, стрелка динамики % жира. Поиск.
2. **Карточка подопечного** — вкладки: Профиль · Здоровье · Замеры · Тренировки · Питание.
3. **Новый замер** — пошаговый ввод с подсказкой-картинкой, где мерить. Складки калипером необязательны.
4. **Результат замера** — крупные цифры, метод расчёта, погрешность, сравнение с прошлым замером.
5. **Прогресс** — графики каждого показателя по датам и фото «до/после» рядом.
6. **Тренировки** — календарь; запись тренировки: дата, длительность, упражнения, подходы, повторы, вес.
   Счётчики: сколько тренировок и сколько часов всего.
7. **Питание** — цель по калориям и КБЖУ, заметки тренера.
8. **Экспорт** — PDF «Прогресс за период» для отправки клиенту.
9. **Согласие** — экран согласия подопечного на обработку данных о здоровье при создании карточки.

**Не делаем в MVP:** оплаты, чат, ИИ-функции, библиотеку упражнений с видео, облачную синхронизацию,
вход по аккаунту.

## Модель данных

Все таблицы имеют `id` (строка UUID — пригодится для будущей синхронизации), `createdAt`, `updatedAt`.

- **clients** — имя, фамилия, пол (`male`/`female`), дата рождения, телефон, почта, мессенджер,
  цель, заметки, фото, `archived` (архив вместо удаления).
- **health** — противопоказания, травмы, ограничения нагрузки, заметки (связь с clients).
- **consents** — дата согласия, версия текста, кто подписал (связь с clients).
- **measurements** — дата, вес, рост, обхваты (шея, грудь, талия, бёдра, плечо, бедро, голень),
  кожные складки (грудь, живот, бедро, трицепс, над подвздошной костью, голень), пульс покоя.
  Все поля, кроме даты и веса, необязательные.
- **photos** — дата, ракурс (`front`/`side`/`back`), путь к файлу (связь с clients).
- **workouts** — дата, время начала, длительность (мин), заметки, самочувствие.
- **workout_exercises** — упражнение, порядок (связь с workouts).
- **sets** — повторы, вес, отдых (связь с workout_exercises).
- **nutrition_plans** — калории, белки, жиры, углеводы, заметки, дата начала.

**Результаты расчёта в базе не храним.** Они вычисляются из замеров при показе. Так исправление
формулы сразу применяется ко всей истории.

## Калькулятор состава тела

Весь код формул — в `src/lib/calc/`: чистые функции без UI и базы данных, каждая с тестами.
Единицы внутри приложения: **сантиметры, килограммы, миллиметры (складки), годы**. Рост в формулах
Lee и FFMI — в метрах. `log10` — десятичный логарифм.

Каждая функция возвращает объект `{ value, method, errorMargin }` или `null`, если данных не хватает.
Невозможные входные данные (например, талия ≤ шеи) дают `null` и понятное сообщение для UI, а не NaN.

### 1. % жира по обхватам — метод ВМС США (Hodgdon–Beckett, 1984)

```
Мужчины: BF% = 495 / (1.0324 − 0.19077·log10(талия − шея) + 0.15456·log10(рост)) − 450
Женщины: BF% = 495 / (1.29579 − 0.35004·log10(талия + бёдра − шея) + 0.22100·log10(рост)) − 450
```
Погрешность ±3–4%. Предупреждение в UI: у очень мускулистых людей завышает % жира.

### 2. % жира по складкам — Jackson–Pollock, 3 точки + формула Siri

Точки: мужчины — грудь, живот, бедро; женщины — трицепс, над подвздошной костью, бедро. S — сумма, мм.
```
Мужчины: D = 1.10938 − 0.0008267·S + 0.0000016·S² − 0.0002574·возраст
Женщины: D = 1.0994921 − 0.0009929·S + 0.0000023·S² − 0.0001392·возраст
BF% = 495 / D − 450
```
Погрешность около ±3.5%. Если есть складки, этот метод считается основным.

### 3. Безжировая масса (LBM) и жировая масса

- Если % жира известен: `LBM = вес × (1 − BF%/100)`, `жировая масса = вес − LBM`.
- Если нет — формула Boer (1984):
```
Мужчины: LBM = 0.407·вес + 0.267·рост − 19.2
Женщины: LBM = 0.252·вес + 0.473·рост − 48.3
```

### 4. Индексы

```
ИМТ = вес / рост_м²
FFMI = LBM / рост_м²
FFMI нормализованный = FFMI + 6.1 × (1.8 − рост_м)
```

### 5. Скелетная мышечная масса — Lee et al. (2000)

Нужны обхваты плеча, бедра, голени и складки на тех же местах (трицепс, бедро, голень).
Исправленный обхват = обхват (см) − π × складка (см), складка в см = мм / 10.
```
SMM (кг) = рост_м × (0.00744·CAG² + 0.00088·CTG² + 0.00441·CCG²) + 2.4·пол − 0.048·возраст + раса + 7.8
пол: мужчина = 1, женщина = 0
раса: 0 по умолчанию (европеоидная), −2.0 азиатская, +1.1 афроамериканская
```
Формула проверена на людях без ожирения. В UI подпись: «мышечная масса — это не то же самое, что
безжировая масса».

### Контрольные примеры для тестов

Значения посчитаны заранее. Тесты должны совпадать с точностью до 0.1.

| Формула | Входные данные | Ожидаемый результат |
| --- | --- | --- |
| ВМС, мужчина | рост 175, шея 38, талия 86 | BF ≈ 17.7% |
| ВМС, женщина | рост 165, шея 33, талия 75, бёдра 100 | BF ≈ 29.4% |
| JP3, мужчина | сумма складок 60, возраст 30 | D ≈ 1.0578, BF ≈ 17.9% |
| JP3, женщина | сумма складок 70, возраст 30 | D ≈ 1.0371, BF ≈ 27.3% |
| Boer, мужчина | вес 70, рост 175 | LBM ≈ 56.0 кг |
| Boer, женщина | вес 60, рост 165 | LBM ≈ 44.9 кг |
| LBM из BF | вес 70, BF 17.7% | LBM ≈ 57.6 кг |
| ИМТ / FFMI | вес 70, рост 1.75, LBM 57.61 | ИМТ ≈ 22.9, FFMI ≈ 18.8, норм. ≈ 19.1 |
| Lee, мужчина | рост 1.75, возраст 30, раса 0; плечо 32/10 мм, бедро 55/15 мм, голень 38/8 мм | SMM ≈ 33.2 кг |

## Дизайн и UX

- Выглядит **презентабельно**: тренер показывает экран клиенту. Чисто, крупные цифры, много воздуха.
- **Светлая и тёмная тема с первого дня.** Все цвета — только из `src/theme/`, никаких цветов в коде экранов.
- Удобно одной рукой в зале: крупные кнопки (не меньше 44×44 pt), числовая клавиатура для замеров.
- Обязательно только имя клиента, остальное заполняется по ходу.
- Интерфейс на русском. Даты — `ДД.ММ.ГГГГ`, десятичный разделитель — запятая.
- У каждого расчёта кнопка «?» с объяснением метода и погрешности простыми словами.
- Пустые состояния с подсказкой, что делать дальше («Добавьте первый замер»).

## Надёжность (главная жалоба пользователей у конкурентов — потеря данных)

- Сохранять сразу при вводе, без кнопки «Сохранить», которую можно забыть.
- Приложение полностью работает без интернета.
- Не удалять данные насовсем: клиенты уходят в архив, удаление замера — с подтверждением.
- Миграции базы только вперёд, никогда не удалять старые миграции.
- В настройках — экспорт резервной копии базы в файл.

## Персональные данные (152-ФЗ)

Замеры, травмы и противопоказания — данные о здоровье, особая категория. Поэтому:
- экран согласия подопечного при создании карточки, согласие хранится в `consents`;
- никакой аналитики, трекеров и отправки данных на сторонние серверы;
- при будущем переходе в облако — только серверы в России.

## Правила кода

- Компоненты — функциональные, с хуками. Один компонент — один файл.
- Логика отдельно от экранов: запросы к базе — в `src/db/`, расчёты — в `src/lib/calc/`.
- Имена в коде — на английском, тексты интерфейса — на русском (пока в `src/i18n/ru.ts`).
- Перед тем как сказать «готово»: `npx tsc --noEmit`, `npx jest` и `npx expo lint` проходят без ошибок.
- Git: коммит после каждого работающего шага, сообщение на русском, кратко о сделанном.

## Как считать задачу выполненной

1. Приложение запускается в Expo Go без красных экранов ошибок.
2. Типы, тесты и линтер проходят.
